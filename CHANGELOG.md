# Changelog

All notable changes to this project are documented here. This project forked from [`@daytona/opencode`](https://github.com/daytona/integrations/tree/main/packages/opencode-plugin); upstream history up to version 0.192.0 is visible [there](https://github.com/daytona/integrations/blob/main/packages/opencode-plugin/CHANGELOG.md).

## [0.1.0] - 2026-08-26

Initial fork release, based on `@daytona/opencode` 0.192.0.

### Added

- `REMOTE_*` configuration resolution (`REMOTE_HOST`, `REMOTE_PORT`, `REMOTE_USER`, `REMOTE_PROJECT_PATH`, `REMOTE_SSH_KNOWN_HOSTS`) with `.env` support in the project root; process env takes precedence (issues #1, #2)
- SSH transport core (`core/ssh.ts`): `SshExecutor` runs commands over the system `ssh` binary (honoring `~/.ssh/config`, keys, agents, jump hosts) with ControlMaster connection reuse and keepalive probes that drop dead connections within ~45s; when `REMOTE_SSH_KNOWN_HOSTS` is set, command execution pins host-key verification to that file (same semantics as git transfers). Also exports `shellQuote` and `sshCommonArgs` helpers (issue #3)

### Changed

- Git layer migrated to the SSH/bare-repo design (issue #5): `git/host-git-manager.ts` reads `REMOTE_SSH_KNOWN_HOSTS` instead of `DAYTONA_SSH_KNOWN_HOSTS`, now always sets `GIT_SSH_COMMAND` for transfers (BatchMode + connection reuse via `core/ssh` helpers; host-key pinning appended only when `REMOTE_SSH_KNOWN_HOSTS` is set), uses `opencode-remote@localhost` for reservation commits, and gains `removeRemote()`; `git/sandbox-git-manager.ts` renamed to `remote-git-manager.ts` with `RemoteGitManager` (no SDK types) running git over `SshExecutor` in the remote workspace and transporting commits through a per-session bare repository (`initFromBare`, `ensureBareRepo`, `pushToBare`).
- `SessionGitManager` rewired onto the SSH transport (issue #6): the constructor now takes the session's `SshExecutor` plus the workspace and bare-repo paths (no `Sandbox`), composing `RemoteGitManager` + `HostGitManager`; the host git remote points at the per-session bare repository, `initializeAndSync()` seeds the remote workspace via `ensureBareRepo`/`initFromBare`, and `autoCommitAndPull()` force-pushes the workspace to the bare repo (`pushToBare`) before the host pull. `HostGitManager` receives the resolved known-hosts file through `SshExecutor.knownHosts` (constructor parameter, `process.env` fallback preserved), so a `REMOTE_SSH_KNOWN_HOSTS` set only in `.env` pins git transfers the same as command execution. The plugin does not compile until dependent modules are migrated (issues #7–#9)
- `core/session-manager.ts` rewritten as `RemoteSessionManager` (issue #7): all `@daytona/sdk` usage and sandbox create/start/refresh/404-reconnect logic removed; `getSandbox` becomes `getRemoteSession`, returning a `RemoteSession` handle (`workspacePath`, `bareRepoPath`, `branchNumber`) resolved from the in-memory cache or storage — storage hits are reconnected over SSH (`mkdir -p` + `ensureRepo`, with recovery via the init flow when the workspace lost its `.git` remotely), and new sessions allocate a number via the local `opencode/N` refs (falling back to the highest numeric entry under `REMOTE_PROJECT_PATH` plus one when git is disabled) before running `SessionGitManager.initializeAndSync`. The constructor takes only the storage dir; the `RemoteConfig`/`SshExecutor` pair is resolved lazily per worktree and a missing `REMOTE_HOST`/`REMOTE_PROJECT_PATH` fails with a config error toast (the old `DAYTONA_API_KEY` failure mode). `deleteSandbox` becomes `deleteSession`: after one best-effort final sync it removes only local state (memory handle, stored mapping, `sandbox-N` git remote) — nothing on the remote machine is ever deleted; a failed final sync no longer blocks deletion. Kept: deletion tombstone + dedup, `ensureNotDeleted` post-await guard, `setProjectContext`/`loadProjectSessions` cache hydration (now storing `RemoteSession` handles), cross-project migration via `getSession`; `hasSandbox` renamed to `hasSession` and `getBranchNumberForSandbox` deleted (handles carry `branchNumber`). The plugin does not compile until dependent modules are migrated (issues #8–#9)
- Session storage schema tracks the remote workspace instead of a sandbox: `SessionInfo.sandboxId` renamed to `workspacePath`, `SandboxInfo`/`SessionSandboxMap` and the `@daytona/sdk` import removed from `core/types.ts`, new `RemoteSession` in-memory session handle type, and `getBranchNumberForSandbox` renamed to `getBranchNumberForWorkspace` in `core/project-data-storage.ts` (issue #4). The plugin does not compile until dependent modules are migrated (issues #5–#8)
- Repositioned as `opencode-remote-plugin`: runs OpenCode sessions on any SSH-reachable machine instead of Daytona sandboxes (documentation updated)
- Package renamed from `@daytona/opencode` to `opencode-remote-plugin`; metadata points to this repository
